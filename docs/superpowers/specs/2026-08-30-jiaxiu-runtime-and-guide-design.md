# 浮玉客问答与运行体验改造设计

## 目标

使配置了 OpenAI 兼容 API 的“浮玉客”能处理检索问答、日常问候、身份介绍和诗意讨论；以非 Docker 的 uvicorn 方式启动时稳定读取仓库根目录 `.env`；改善移动端体验；精简影像页面的访客文案；提供本地与 Docker 一键启动脚本。

## 导览问答

`AgentService` 将把回答分为两类：

- 有检索证据时，将证据作为不可信资料传给模型，要求仅对引用性事实作出处约束，并返回可选的证据 ID。
- 无检索证据时，仍调用已配置模型，允许回答问候、身份和围绕甲秀楼、诗歌阅读的开放讨论；不附带伪造引文。模型调用失败时，以本地、非检索式的导览文案回应这些日常问题。

提供方请求优先使用 OpenAI 兼容的结构化输出；若服务端不接受该选项，安全地使用 JSON 指令的兼容请求。无论哪种方式，服务端都会校验返回格式、筛除未检索到的引文 ID，并在需要事实依据而无证据时降级为本地回答。

## 配置与容器

Pydantic 设置的 `env_file` 改为由 `config.py` 位置推导出的仓库根目录 `.env`，不依赖进程工作目录。Docker Compose 继续以环境变量注入配置；镜像将继续只复制 API 运行所需源码、锁定依赖、研究数据库和入口脚本。Dockerfile 与入口脚本会检查 Python 运行路径和依赖是否与该布局一致。

## 前端

影像记录页会移除扫描页、印刷页、“影像 / 第 N 幅”与“高清影像”等用户可见文字。记录以作品/来源已有标题为主；查看器内部保留 `01`、`02` 等缩略页序号作为切换控件。

移动端优先保证 320px 至 760px 宽度下：导航不遮挡内容、导览面板不被场景控件压住、影像查看器的标题和控制键可换行且可触控、卡片与正文不产生横向溢出。桌面样式保持现有视觉语言。

## 启动脚本

在仓库根目录新增 POSIX shell 脚本：一个创建/同步 Python 环境并启动 API 和 Vite 前端；一个校验 Docker Compose 配置后构建并启动服务。脚本会从仓库根目录执行，转发中断信号并清理各自的后台子进程。README 将说明所需的 `uv`、Node/pnpm、Docker 条件与命令。

## 验证

- 后端单元测试覆盖：根目录 `.env` 读取、无证据时模型仍被调用、问候/身份的本地降级、无效模型输出不会泄漏为引用。
- 前端测试覆盖影像文案不再渲染，并保留缩略页编号。
- 执行后端测试、前端测试、lint 与生产构建；执行 `docker compose config` 校验容器编排。
- 使用至少一个窄屏视口进行构建后的响应式检查。
